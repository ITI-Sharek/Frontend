## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

Document the result of each ShareK Frontend Constitution gate:

- **Route composition boundary**: Identify route files/layouts touched and confirm they contain composition, shell, metadata, prefetch, loading, or error handling only.
- **TanStack routing**: Confirm route changes use TanStack Router file-route conventions, loaders, redirects, pending components, and error components where appropriate.
- **Feature ownership**: Identify the owning `src/modules/<feature>/` module and any public exports added to that module's root `index.ts`.
- **Module isolation**: Confirm no lateral imports between `src/modules/*`; cross-feature assembly must happen in route/page composition.
- **Shared placement**: Confirm anything added to `src/shared/` is feature-agnostic and has real reuse; otherwise keep it feature-local.
- **State ownership**: Confirm server-originated data uses TanStack Query and feature services; confirm client-only UI state uses local state or Zustand.
- **API boundary**: Confirm there are no inline axios calls in components; HTTP calls live in services, and query/mutation hooks are separate.
- **Typing and validation**: Confirm forms/API payloads use Zod or shared typed envelopes where applicable, and backend errors are not parsed ad hoc.
- **Import strategy**: Confirm cross-layer imports use `@/*` aliases and external module consumers import through root feature barrels only.
- **Server/browser split**: Confirm browser-only APIs stay out of route loaders and server execution paths.
- **Validation plan**: List unit, component, integration, or E2E checks required for the changed behavior.
